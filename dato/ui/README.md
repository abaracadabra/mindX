# dato UI — naming & data (modular, parsec-wallet-ready)

A zero-build UI for **dato naming** and **dato data**, in the same `dato/` folder,
built to drop into **parsec-wallet** as a modular feature. Plain ESM JavaScript
(no framework, no build step) in parsec-wallet's view idiom (`el/btn/input` +
`(): HTMLElement` factories + a router/navigate), so it runs standalone in a browser
**and** imports cleanly into parsec-wallet's Vite app.

## What it handles

- **Naming** (`dato-name`) — compose `<handle>.<tier>.<root>` where the tier label
  *declares* permanence (immortal | immutable | mutable) and roots are extensible.
  - Local roots (default `blockchain`) register free into the dato registry.
  - **ar.io ARNS roots (`ar`) are a PURCHASE** (HyperBEAM/ARIO). The UI surfaces the
    purchase requirement and **hands off** to ar.io / parsec-wallet's `name-manage`
    (`ario`) flow rather than pretending an ARNS name is free.
- **Commerce** (`dato-commerce`) — spawn a DAIO-owned dato with a join fee, then
  **request-to-join paying an x402 fee** (agentic commerce). A `settleX402` hook
  (set by the parsec adapter / CLI) mints the x402 payment; standalone attaches a
  demo receipt so the full flow is exercised. Members + fees are tracked per dato.
- **Deploy** (`dato-deploy`) — **hand off the dato contracts to the OVERLORD deployer**
  and bind on-chain. Shows per-contract deployment status (DatoCore · DatoNamingRegistry
  · DatoMembership), a "Hand off to OVERLORD deployer →" action (in-app navigate via
  `deployerHandoff`, or opens DeltaVerse `pages/deploy.html`), and once deployed a
  "Bind UI to on-chain dato" that points the client at the deployed addresses. The
  dato suite is registered in DeltaVerse `deploy/suites.json` (id `dato`); deployments
  are read from `live/contracts.json`.
- **Data** (`dato-data`) — commit data at a permanence tier and view records/proofs:
  - **immortal** → permanent Arweave upload (200-yr); proof = Arweave tx id (the
    real ANS-104 upload runs server-side via `tools/arweave_turbo` or the dato AO
    process; the UI records intent + sha256 and shows `pending-arweave-upload`).
  - **immutable** → sha256 hash-lock (`anchor:<sha>`); re-commit with different bytes rejected.
  - **mutable** → editable, versioned.

## Files
`dom.js` (parsec-compatible el/btn/input/select/toast) · `client.js` (`DatoClient`:
naming + permanence + ARNS-purchase, localStorage by default, pluggable backend) ·
`views.js` (`createDatoUI` → hub/name/data) · `parsec.js` (`registerDatoViews` adapter) ·
`app.js`+`index.html`+`styles.css` (standalone mount).

## Run standalone (no build)
```bash
cd dato/ui && python -m http.server 8088   # then open http://localhost:8088
```

## Include in parsec-wallet (modular)
In `parsec-wallet/src/main.ts`:
```ts
import { registerDatoViews } from '<path>/dato/ui/parsec.js';
import { registerView } from './lib/router';
import { store } from './lib/store';
import * as dom from './lib/dom';                          // parsec's own helpers

registerDatoViews({
  registerView,
  navigate: (v) => store.navigate(v),
  dom,                                                     // optional; falls back to dato's bundled dom.js
  controller: () => store.get().accounts[store.get().activeAccountIndex]?.address,
  arioHandoff: () => store.navigate('name-manage'),        // ARNS purchase → parsec's ario flow
  settleX402: async (quote) => {                            // mint the x402 join-fee payment
    const cred = await parsecX402.issueForDato(quote);      // parsec's x402 signer → X-PAYMENT
    return { receipt: cred.nonce, amount: quote.feeMicroUSD };
  },
  // deployer handoff: bind the Deploy view to DeltaVerse's OVERLORD deployer + on-chain
  deployerHandoff: () => store.navigate('deploy'),          // in-app DeltaVerse deployer
  deploymentsSource: '/live/contracts.json',                // live deployed addresses
  onchainBackend: (addr) => makeDatoOnchainBackend(addr, store.signer()),  // ethers-backed reads/writes
  // backend: <DatoClient backend targeting the dato AO process via aoconnect / mindX /dato HTTP>
});
```
Then add `dato-hub` to parsec-wallet's navigation. To settle data/naming on-chain,
pass a `backend` that targets the dato AO process (`dato/data/ao_process.json`, see
[`../ao/DEPLOY.md`](../ao/DEPLOY.md)) or the mindX `/dato` API.

## Deployer handoff + on-chain verification
The `dato-deploy` view hands the dato contracts to the DeltaVerse OVERLORD deployer
(`pages/deploy.html`, suite `dato`). On **deploy-to-live**, the deployer writes a
per-chain **verification store** at `live/verify/<ChainName>/<Contract>/` — the exact
compiled `.sol` source, the complete `abi.json`, the Solidity `standard-input.json`
(for Etherscan / `forge verify-contract`), and `deployment.json` (address, compiler,
optimizer, evmVersion). Generated by `DeltaVerse/scripts/verify-bundle.mjs` (run
automatically by `deploy-stack-anvil.mjs`; for the browser deployer, run it against
the downloaded `live/deployed.json`).

## Verified
Client logic (compose, local register, **ARNS purchase gate**, immutable lock,
mutable versioning, immortal-pending, **spawn + fee-gated join**) + all **five** views
render (jsdom) + the parsec adapter registers
`dato-hub`/`dato-name`/`dato-data`/`dato-commerce`/`dato-deploy`. The dato suite is
registered in the DeltaVerse deployer (3 contracts indexed in `live/contracts.json`),
and `verify-bundle.mjs` emits a complete `live/verify/Base/Dato*/` bundle.

## Headless / agentic commerce
For autonomous agents, the same dato lifecycle (spawn → join-with-x402-fee →
commit) runs from the **CLI** — `python -m dato.cli …` — which settles join fees
over x402. See the "CLI — agentic commerce" section in [`../README.md`](../README.md).
